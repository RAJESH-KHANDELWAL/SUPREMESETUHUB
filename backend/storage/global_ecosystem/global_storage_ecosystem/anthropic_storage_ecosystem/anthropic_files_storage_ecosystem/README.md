# Anthropic Files Storage Ecosystem

Models Anthropic Claude Platform's documented Files API as a provider-managed, workspace-scoped file resource service.

## Documented operations

- Upload a file and receive a provider `file_id` and metadata.
- List files with pagination and retrieve file metadata.
- Reference an uploaded file in supported Messages API content blocks.
- Delete a file.
- Set optional expiry at upload (3,600 to 7,776,000 seconds: 1 hour to 90 days).

## Lifecycle and constraints

- Files belong to a workspace, not an application end user or conversation.
- A key with access to the workspace can access its files. Maintain a server-side tenant-to-workspace and tenant-to-file mapping; never trust a client-supplied file ID.
- For multitenant isolation, use a separate workspace per tenant where account/workspace limits and entitlements permit.
- Uploaded files are not downloadable through the Files API. Download is supported for eligible files generated by skills or code execution.
- Files cannot be modified or renamed after upload. Replace by uploading a new file and deleting the old file.
- Deletion is irreversible. Apply retention and deletion policy before invoking it.
- Current documented maximum file size is 500 MB per file; verify account-level quotas and current provider limits before production enforcement.

## Ownership boundary

This folder owns storage metadata contracts, tenant mapping requirements, lifecycle policy and capability declarations. API authentication, HTTP calls and endpoint schemas remain in `backend/api/global_ecosystem/global_api_ecosystem/anthropic_api_ecosystem/anthropic_files_api_ecosystem/`.
