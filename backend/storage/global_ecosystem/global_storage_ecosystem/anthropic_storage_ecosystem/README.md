# Anthropic Storage Ecosystem

Provider-specific storage boundary for Anthropic Claude Platform file resources. This ecosystem models documented Anthropic file-storage capabilities; it is not a general-purpose cloud drive, object store, or backup provider.

## Child ecosystems

- `anthropic_files_storage_ecosystem/` — workspace-scoped Files API resources: upload, metadata/list, reference, expiry and deletion.
- `anthropic_managed_agents_session_storage_ecosystem/` — session-scoped files and generated session outputs used by Managed Agents environments.

## Responsibility boundary

- **Storage ecosystem:** storage metadata, ownership mapping, lifecycle policy, tenant isolation requirements, capability declarations and storage readiness.
- **Anthropic API ecosystem:** API authentication, HTTP clients, endpoint calls, request/response schemas and API-version handling.
- **Application/database layer:** authoritative mapping from SUPREMESETUHUB tenants/users to provider workspace IDs and file IDs.

Do not duplicate Anthropic API clients or credentials here. Never accept an Anthropic `file_id` from an untrusted client as proof of ownership.

## Important provider constraints

- Files API resources are workspace-scoped; keys with access to a workspace can access that workspace's files.
- Use separate Anthropic workspaces as the documented isolation boundary for tenants where supported and appropriate.
- Uploaded files cannot be downloaded through the Files API; downloadable files are generated by supported tools such as code execution or skills.
- Files cannot be modified or renamed in place. Replace by uploading a new file and deleting the old one.
- Optional file expiry is configured at upload and supports 1 hour through 90 days.
- This is not a generic file-sync, public sharing, folder hierarchy, or long-term backup service.

## Bharat-to-global scope

The ecosystem can be deployed for Bharat, regional and global tenants, with Normal, Professional, Advanced, Enterprise and Supreme service maturity targets. These are product coverage targets, not claims of Anthropic regional availability, data residency, legal approval or account entitlement.

Domain coverage (technology, business, education, culture, health/wellness and lawful adult-only contexts) is application policy, not a grant of permission to upload or process any particular content. Apply age assurance, consent, privacy, retention, security, takedown and jurisdiction-specific review where relevant. Minors, coercion, exploitation and non-consensual intimate imagery are prohibited.

## Integration status

Catalog and local contracts only. Live Anthropic connectivity is `NOT_CONFIGURED` until authorized credentials, workspace permissions, successful API health checks and end-to-end tests are verified. Never commit secrets or personal data.
